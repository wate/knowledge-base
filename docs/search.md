検索方式
=========================

`search`サブコマンドが使う3つのモードと、順位が決まる仕組みをまとめる。
記載した数値はDuckDB `v1.5.5`(fts拡張`6814ec9`)と、275文書のDBで実測した値である。

検索モード
-------------------------

3つのモードがあり、既定はBM25とする。

| モード           | 指定方法   | 使う索引   |
| ---------------- | ---------- | ---------- |
| BM25             | 指定なし   | DuckDB FTS |
| ベクトル検索     | `--vector` | embedding  |
| ハイブリッド検索 | `--hybrid` | 両方       |

- `knowledge-base.mjs search <クエリ>`は既定のBM25で検索する
- `knowledge-base.mjs search --vector <クエリ>`はベクトル検索を行う
- `knowledge-base.mjs search --hybrid <クエリ>`は両方を合算する
- `--top N`で取得件数を指定する(既定`20`、上限`100`)
- `--json`を付けるとJSONで出力する

結果は章(`chapters`)単位で返す。
同じ文書の複数の章が並ぶことがある。

BM25
-------------------------

DuckDB FTS拡張の`match_bm25()`を使う。
順位はOkapi BM25の式で決まり、次の3つの要素が効く。

### IDF(語の珍しさ)

- 索引全体で珍しい語ほど寄与が大きい
- どの文書にも現れる語は寄与が小さい

### 語の頻度の飽和(`k`)

- 章の中で出現回数が多い語ほど寄与が大きい
- ただし出現回数に比例せず、一定回数で頭打ちになる
- 頭打ちの度合いを`k`で調整する(`k1`とも呼び、既定は`1.2`)
- 値を大きくすると出現回数の影響が残り続ける

### 文書長正規化(`b`)

- 長い章は語が当たりやすく有利になるため補正する
- 補正の強さを`b`で調整する(既定は`0.75`)
- `b = 0`で補正なし、`b = 1`で完全に補正する

### 索引の対象

- 索引は`chapters`テーブルに対して作る
- 対象列は`chapters.heading`と`chapters.content_wakati`の2列である
- `content_wakati`はLinderaで分かち書きした本文(`content`)である
- 見出しと本文は同じ重みで検索される(列ごとの重みは指定できない)
- 列の重み指定は`create_fts_index()`に引数が無いため、再作成しても設定できない
- 検索クエリもLinderaで分かち書きしてから`match_bm25()`へ渡す

### スコアの性質

- 値は`0`以上の実数で、上限は無い
- 実測値は語によって変わる
    - `制約`は`0.052〜3.183`、`設定`は`0.058〜1.515`、`テスト`は`0.062〜2.142`
- 負の値は3語の実測では`0`件だった
- 値はそのまま順位に使うため、しきい値による足切りはしていない

### パラメータの調整

`match_bm25()`は次の引数を受け取る。

```
match_bm25(input_id, query_string, fields := NULL, k := 1.2, b := 0.75, conjunctive := 0)
```

- `k`と`b`はクエリ時に指定できる(索引の再作成は不要)
- `fields`で検索対象の列を絞れる(既定は索引した全ての列)
- `conjunctive`を真にすると、全ての語を含む章だけを返す
- 現在の`lib/search.mjs`は`k`・`b`・`fields`・`conjunctive`を渡していない
- 既定値のまま動くため、調整する場合は`searchBM25()`へ引数を追加する

### 更新の扱い

- FTS索引は元テーブルの変更に追随しない
- `sync`は取り込み後に索引を作り直すため、通常の運用では差分が出ない
- 手動で作り直す場合は`lib/ingest.mjs`の`rebuildFtsIndex()`を使う

ベクトル検索
-------------------------

`intfloat/multilingual-e5-small`で作った384次元のベクトルを使う。

### embeddingの入力

- 文書全体は`documents.summary`をベクトル化する(`summary`は見出しツリー)
- 章は`chapters.summary`をベクトル化する(`summary`は見出しと最初の段落)
- 登録時は`passage`プレフィックスを付けて生成する
- 検索クエリは`query`プレフィックスを付けて生成する
- 入力が要約であるため、本文全体の類似ではなく要約の類似で並ぶ

### 類似度

- `list_cosine_similarity(embedding, クエリベクトル)`で類似度を出す
- 類似度はおおむね`0`から`1`の範囲に収まる
- 類似度に他の項を加えた複合スコアで並べる(次節で示す)

ハイブリッド検索
-------------------------

まず`documents.embedding`の類似度で上位`search.top_n_documents`件(既定`20`)の文書に絞る。
次に、その範囲の章を対象にベクトルスコアとBM25スコアを合算する。

- 合算は`ベクトルスコア × 0.7 + BM25スコア × 0.3`とする
- `0.7`と`0.3`は`search.hybrid_weights.vector`と`search.hybrid_weights.bm25`で変更する
- ベクトルスコアはmin-max正規化したcosine項とPageRank項を含む(次節で示す)
- BM25スコアは生の値を使う(正規化しない)
- そのため桁の大きい語ではBM25の寄与が支配的になりやすい

スコアの全体像
-------------------------

### ベクトルスコアの式

```
ベクトルスコア = cosine(min-max正規化) × 0.65
              + PageRank(min-max正規化) × 0.05
              + heading_weight(正規化) × 0.2
              + position × 0.1
```

- `cosine`は`list_cosine_similarity()`の値を、候補となった章の最小値を`0`・最大値を`1`とするmin-max正規化をした値である
- `PageRank`は`documents.pagerank_score`を最小値`0`・最大値`1`へmin-max正規化した値である
- `heading_weight`は見出しレベル別の重みを`9.0`で割った値である
- `position`は`1 / (chunk_index + 1)`とする

### 係数の調整箇所

- 実装は`lib/search.mjs`の`WEIGHTS`が`search.weights`を読む
- `search.weights`の`cosine`・`pagerank`・`heading`・`position`で変更する
- `search.hybrid_weights`の`vector`・`bm25`で変更する
- `heading_weights`の`1`から`6`で変更する(見出しレベル別)
- 既定値は`cosine 0.65`・`pagerank 0.05`・`heading 0.2`・`position 0.1`である
- `search.weights`の合計は`1.0`にする(`lib/config.mjs`が検証する)
- 設定方法は[設定リファレンス](config-reference.md)を参照

課題と制約
-------------------------

### PageRank項

- PageRankは`sync`の後に計算し、`documents.pagerank_score`へ書き込む
- リンク解析の対象はローカルソースのディレクトリとし、Webソースは対象外とする
- 実測は`doc_links`112件、`pagerank_score`は42種類(`0.00233〜0.02570`)である
- 正規化後の値は半数以上が`0`に張り付き、上位だけが`1.0`に近づく分布になる

### 重みと正規化

- cosineの生値は`0.70〜0.93`に収まり、文書どうしの差が小さい
- cosineを正規化せずに重み`0.5`を掛けると、pagerank項が順位を支配しやすい
- このためcosineをmin-max正規化し、重みを`cosine 0.65`・`pagerank 0.05`とする
- この構成では5クエリの上位10件に現れる異なり章数が`46`である(正規化しない場合は`14`)
- PageRank項の寄与は小さく、関連度が近い文書の差を補う役割にとどめる

### BM25の制約

- 列ごとの重みは指定できない
- ステマー・ストップワード・`ignore`は索引作成時の設定であり、現在は既定値のまま
- 索引は章単位であるため、文書全体の長さは考慮されない
